# Eco-Matic Presentation Script

This script follows the required documentation outline (Project Overview → Appendix) and matches the refreshed 10-slide deck. Target duration: 8–10 minutes.

| Slide | Cues & Visual Reminders | Speaker Script |
| --- | --- | --- |
| 1. Title | Accent block + badge “Trash-to-credit • SDG12 • Spectre.Console” | “Good day everyone, I’m Seanix and today I’m presenting **Eco-Matic**, my C# console vending machine that mixes vending, recycling incentives, and Sustainable Development Goal 12 on responsible consumption. This deck walks through the required documentation, and the console demo is ready after the talk.” |
| 2. Project Overview | Four bullets: Purpose, Features, Target Audience, Tech Stack | “Eco-Matic simulates a vending kiosk that rewards sustainable habits. Purpose-wise, it gives me a sandbox to showcase OOP plus file I/O, while demonstrating how ‘trash-to-credit’ can motivate cleaner streets in Cebu. Feature highlights include customer and admin roles, CSV-driven inventory, and live event logging. The audience is my instructors, classmates, and sustainability advocates who need a clear prototype. Tech stack is .NET 9 with Spectre.Console for the UI, CSV storage, and ANSI styling for dashboard-like tables.” |
| 3. Requirements | Bullets for software, installation, system | “To run it you only need the .NET 9 SDK and Spectre.Console, ideally inside VS Code or VS 2022. Setup is simply `dotnet restore`, `dotnet build`, then `dotnet run --project eco-matic/eco-matic.csproj` from the repo root so the data folder copies. Any Windows laptop that handles console apps qualifies as system hardware.” |
| 4. File Handling Overview | Bullets: Inventory, Event Log, Safeguards | “File handling is the backbone. Inventory CSV holds each slot’s type, name, price, stock, and nutrition data. The event log CSV captures purchases, recycle credits, and admin actions with timestamps. At runtime I load arrays from CSV, rewrite inventory for structural changes, and append to the log for every transaction. Safeguards check headers, validate numbers, and auto-regenerate missing files so demos never break.” |
| 5. Code Structure | Bullets on classes, helpers, modularity | “The `EcoMatic` class orchestrates menus, balance tracking, inventory mutations, and logging. `VendingItem` is the abstract base for Snack, Drink, and Misc items; polymorphism lets me print flavor text and CSV entries cleanly. Helpers such as `Write`, `TransactionTracker`, `RecycleTracker`, and `SalesReport` keep responsibilities isolated even though everything still sits in `Program.cs`. Constants define slot and stock limits to avoid magic numbers.” |
| 6. User Interface | Bullets on design, customer/admin flow, errors | “I shaped the UX with Spectre.Console tables, color-coded stock dots, and receipt summaries. Customers insert bills, examine or buy items, recycle materials, then cash out with change and a concise receipt. Admins enter a password to restock, add or remove items, view/clear logs, and inspect the sales report. The `Write` helper highlights invalid IDs, bills, or ranges, guiding users back on track.” |
| 7. Challenges & Solutions | Bullets: CSV corruption, arrays, single-file, storytelling | “Challenges? CSV corruption risk was real, so I added validation plus an auto-rebuild routine. Array-based constraints meant I had to reset trackers after every customer session. The single-file requirement pushed me to use regions and helper classes for sanity. Finally I made sure the eco narrative stayed visible by weaving recycle credits into the UX copy.” |
| 8. Testing | Bullets: cases, results, tooling, limitations | “Testing covered common paths—normal purchases, insufficient funds, sold-out items, recycling boundaries, and all admin actions. After each scenario I reviewed CSV diffs and log lines to verify persistence. I run `dotnet build` before demos to ensure the binaries match the data. Main limitation: tests are still manual, so future work includes scripted regression tests.” |
| 9. Future Enhancements | Bullets: refactor, analytics, UX, performance | “Next steps include splitting `Program.cs` into multiple files and replacing arrays with collections. I want configurable recycle catalogs and a multi-day analytics dashboard. Longer term, a GUI or web client would make this kiosk-ready with remote admin control. Performance tweaks like inventory valuation, restock forecasting, and caching round it out.” |
| 10. Conclusion & Appendix | Conclusion bullets + dual-column appendix | “In conclusion, Eco-Matic sharpened my skills in OOP, file I/O, and UX storytelling within a console app. It proves sustainability narratives can live inside technical deliverables, and it already ships with documentation plus an MIT license. The appendix links to source files and references such as Spectre.Console docs, .NET file I/O docs, and UN SDG 12 material. I’m ready for questions or a live demo.” |
